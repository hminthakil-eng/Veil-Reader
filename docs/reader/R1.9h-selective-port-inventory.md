# R1.9h — Selective-Port Inventory & Conflict Map

Status: DRAFT / consolidation-preflight artifact  
Canonical Reader tip at audit time: `test/r1-9g-consolidated-regression-guards` (#239)

## Goal

Prevent legacy Reader branches from being merged wholesale after R1.10. Classify older work as:

- **PORT** — still missing and evidence-backed.
- **RECHECK** — potentially useful, but must be revalidated against the current Reader stack.
- **SKIP** — already replaced, duplicated, or conflicts with canonical ownership.

## PR #220 — P2.2b PDF reliability

### PORT after R1.10

#### 1. Fragment restoration shim

Files:
- `ReaderFragmentRestoration.kt`
- the paired `MainActivity` fragment-factory install/discard hooks

Why:
- the current canonical tip does not contain `ReaderFragmentRestoration.kt`;
- PR #220 handles FragmentManager restoring constructor-bound Readium navigator fragments before Compose can rebuild the publication-bound factory;
- its PDF dummy publication works around the Readium 3.4 PDF restore path that expects a non-empty reading order.

Port rule:
- port the restoration mechanism as one atomic slice;
- verify EPUB and PDF Activity recreation/rotation;
- verify it does not compete with R1.9 SavedState locator recovery;
- do not port older ReaderScreen state ownership with it.

#### 2. PDF end-to-end reliability instrumentation

File:
- `ReaderPdfReliabilityInstrumentedTest.kt`

Why:
- absent from the canonical tip;
- covers real PDFView gestures, zoom, pan, layout toggle, page resume and rotation.

Port rule:
- adapt selectors/control names to the current Reader UI;
- keep current R1.5 PDFView-as-authoritative zoom semantics;
- do not copy obsolete production behavior merely to make the old test pass.

#### 3. SAF DocumentsUI reset

File:
- `ReaderSafImportInstrumentedTest.kt`

Missing line in current tip:
`pm clear com.google.android.documentsui`

Why:
- removes suite-order dependence from DocumentsUI state.

Classification:
- PORT as test-harness hardening.

#### 4. Repository shutdown join for instrumentation

Files:
- `LocalLibraryRepository.closeForTest()`
- `AnnotationDurabilityInstrumentedTest`
- `RoomRuntimeRepositoryInstrumentedTest`

Current tip:
- `closeForTest()` only calls `scope.cancel()`;
- tests close the in-memory Room database immediately afterward.

PR #220:
- cancellation is followed by joining the repository root job;
- test teardown waits before `db.close()`.

Why:
- prevents asynchronous observers from touching a closed database.

Classification:
- PORT as test-only lifecycle hardening, preserving current production ownership and write sequencing.

### RECHECK

#### PDF scroll control placement

PR #220 places PDF continuous-scroll control inside `PdfZoomControls`.

Current canonical stack still maps the shared `ReaderAppearance.scroll` into PDFium preferences, but R1.9f removed dead PDF Appearance UI and current PDF chrome opens Zoom directly.

Decision:
- product/UI decision required after R1.10;
- reintroduce only through the current ownership model;
- do not copy the old whole-`ReaderAppearance` callbacks.

### SKIP

#### Old PDF zoom ownership implementation

Do not port PR #220's mutable local zoom owner.

Reason:
- R1.5/#228 already replaced it with PDFView-authoritative zoom and a display-only mirror.

#### Old LocalLibraryRepository appearance owner

Do not port:
- `_appearance`
- `loadAppearance()`
- `saveAppearance()`

Reason:
- conflicts with canonical SettingsStore/DataStore ownership and later R1 appearance-convergence work.

#### Old Reader preference mapping tests already covered

Do not duplicate PDF mapping assertions already present in the current `ReaderPreferencesTest` / newer contracts.

## PR #221 — Direct Settings access

### PORT after Reader reliability gate

- `LibraryScreen` exposes Settings in compact and wide headers

Why:
- direct one-move Settings access is still absent from the canonical tip;
- it does not require a second settings architecture.

Port rule:
- reimplement against the current Library UI, not by merging the old branch wholesale.

### RECHECK

Reader chrome label:
- PR #221 renames EPUB `Appearance` to `Settings`.

Decision:
- defer naming to the post-core UX integration pass;
- current implementation is explicitly `EpubAppearancePanel`, so naming should reflect the final information architecture rather than legacy wording.

### SKIP

Do not port PR #221's older Reader-panel structural assumptions. R1.9f has already made the current panel EPUB-only and newer appearance ownership rules supersede the old stack.
