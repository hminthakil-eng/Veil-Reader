## Runtime blockers / acceptance risks

### B1 — Close-path durability window

Severity: **HIGH acceptance risk; not yet reproduced**

Current close path:

1. `ReaderScreen.closeReader()` records a `FINAL_SNAPSHOT`.
2. `ReaderViewModel.closeBook()` calls `finishCurrentSession()`.
3. `finishCurrentSession()` calls `library.flushProgress(bookId)`.
4. `flushProgress()` moves the latest pending progress into the asynchronous storage queue.
5. Reader route then closes and its SavedState checkpoint is normalized away.

Important: `flushProgress()` is an enqueue boundary, not a durable ACK.

Therefore a process loss in the window after checkpoint removal but before the queued Room write commits could lose the newest locator.

R1.10 must reproduce or disprove this deterministically. Do not patch from static reasoning alone.

Required evidence:
- final committed locator sequence;
- `locator_save_enqueued`;
- route checkpoint state;
- `locator_persisted`;
- relaunch locator.

### B2 — FragmentManager navigator recreation gap

Severity: **HIGH acceptance risk; current tip lacks the old proven shim**

The current `MainActivity.onCreate()` calls `super.onCreate()` without installing a Readium-aware FragmentFactory.

Legacy PR #220 contains:
- `ReaderFragmentRestoration.kt`;
- a minimal one-link PDF restoration publication;
- MainActivity factory installation before `super.onCreate()`;
- disposal of restored dummy navigator fragments immediately after restoration.

That mechanism is absent from the current canonical tip.

R1.10 must exercise real Activity recreation / rotation for both EPUB and PDF. If FragmentManager cannot recreate the constructor-bound navigator safely, selectively port the #220 shim as one isolated slice.

Do not merge #220 wholesale.

### B3 — PDF end-to-end verification gap

The canonical tip does not yet contain #220's `ReaderPdfReliabilityInstrumentedTest`.

This is a verification gap, not a proven production bug.

After B2 is resolved:
- adapt the test to current controls;
- preserve R1.5 PDFView-authoritative zoom ownership;
- verify pinch, double-tap, pan, layout policy, page resume and rotation.

## R1.10 minimum acceptance scenarios

For both EPUB and PDF:

1. open and reach a non-initial locator;
2. Activity recreation / rotation;
3. background → foreground;
4. legitimate process recreation;
5. final-close durability boundary;
6. rapid locator churn around progress coalescing;
7. stale persisted ACK while a newer checkpoint exists;
8. explicit locator > checkpoint > Room precedence.

EPUB additionally:
- PAPER preview emits no false page-turn commit;
- PAPER commit persists exactly once;
- SLIDE directional behavior is animated only when applicable;
- continuous scroll commits progress without page-turn credit.

PDF additionally:
- no hidden EPUB page-turn preference affects PDF behavior;
- zoom remains PDFView-owned;
- page/resume survives recreation.
