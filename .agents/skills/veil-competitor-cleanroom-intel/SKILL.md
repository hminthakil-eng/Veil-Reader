# Competitor Intelligence — Clean Room

## Evidence
Collect official documentation, observed behavior, public issue discussions, review themes and legally obtained app instrumentation where permitted. Distinguish observed, inferred and unverified behavior. Do not claim to have opened or tested an APK unless an actual authorized test was performed.
When using user-provided APK files, hash/inventory them in isolation; treat binaries as untrusted; do not execute unsigned third-party builds on privileged systems or ship them.
Extract feature requirements, gesture patterns, failure modes and performance targets as neutral behavior descriptions. Do not transplant or translate decompiled proprietary source, obfuscated assets, private resources, license keys or DRM handling.

## Parity matrix
For each feature: competitor, exact version/date, what user likes/dislikes, Veil baseline, user-visible acceptance standard, open-source reusable alternative, legal license, owner, risk, benchmark, verification evidence and planned follow-up PR.
Prioritize critical reading path: import/open, navigation/Paper, resume, typography, notes/search, PDF, TTS, storage and offline recovery. Distinguish essential parity from intentionally differentiated identity.
Candidate external code requires independent architecture review and license gate, not copy-paste-first.

## Output
Publish the testable matrix and source links, then issue targeted, reversible tasks. Never mark feature parity green on descriptions or mockups alone.
